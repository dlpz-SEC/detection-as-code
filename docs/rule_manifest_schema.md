# Rule Manifest Schema (`rule_manifest.json`)

Machine-readable export of every **production**-lifecycle detection rule, consumed by [ADTE](https://github.com/dlpz-SEC) (Autonomous Detection Triage Engine) to map triaged incidents back to detection coverage, confidence weighting, and tuning guidance.

- **Producer:** [`scripts/export_manifest.py`](../scripts/export_manifest.py)
- **Location:** `docs/rule_manifest.json`
- **Current schema version:** `1.0`
- **Refresh:** regenerated by the `Rule Manifest Export` CI stage on every push to `main`; committed back only when rule content changes (`ci: update rule manifest [skip ci]`).

## Generation contract

- **Filter:** a rule is included **iff** `custom.lifecycle` normalizes (trim + lowercase) to `production`. Every other lifecycle — `draft`, `experimental`, `deprecated`, missing, or malformed — is excluded.
- **Deterministic:** entries are sorted by `path`; technique lists preserve first-seen order with duplicates removed; paths are POSIX (`/`) regardless of the OS that generated them. The same rule set produces a byte-identical file.
- **Idempotent:** `generated_at` is the only volatile field. If the rule content is unchanged, the previous file (and its timestamp) is preserved untouched — so `generated_at` means **"when the production rule set last changed,"** not "when the exporter last ran." Consumers can treat it as a content-change watermark.

## Top-level object

| Field | Type | Description |
|---|---|---|
| `schema_version` | string | Manifest schema version. Bumped on any breaking structural change. Currently `"1.0"`. |
| `generated_at` | string | UTC timestamp, `YYYY-MM-DDTHH:MM:SSZ`. Content-change watermark (see above). |
| `rule_count` | integer | Number of entries in `rules` (production rules only). |
| `rules` | array\<RuleEntry\> | Production rule entries, sorted by `path`. Empty array when no production rules exist. |

## `RuleEntry` object

| Field | Type | Nullable | Description |
|---|---|---|---|
| `id` | string | no¹ | Rule UUID (Sigma `id`). **ADTE's join key.** |
| `title` | string | no | Human-readable rule title (Sigma `title`). Falls back to `"Unknown"` if absent. |
| `path` | string | no | Repo-relative POSIX path, anchored at the rules dir, e.g. `rules/windows/credential_access/lsass_memory_access.yml`. |
| `techniques` | array\<string\> | no | MITRE ATT&CK technique/sub-technique IDs, uppercased, `attack.` stripped: `attack.t1003.001` → `T1003.001`. Tactic-only tags are excluded. May be empty. |
| `lifecycle` | string | no | Always `production` (normalized). |
| `confidence` | string \| null | yes | Normalized `custom.confidence` (`high`/`medium`/`low`), or `null` if unset. |
| `confidence_weight` | number | no | Derived from `confidence` (see mapping). |
| `false_positive_rate` | string \| null | yes | `custom.false_positive_rate` (`low`/`medium`/`high`), or `null` if unset. |
| `tuning_notes` | string \| null | yes | `custom.tuning_notes`, trimmed. Multi-line; `\n`-separated. `null` if unset. |

¹ Schema validation (CI stage 1) enforces a valid UUID on production rules. The exporter additionally emits a non-fatal warning if it observes a missing or duplicated `id`, since either silently breaks ADTE's join.

## `confidence_weight` mapping

| `confidence` | `confidence_weight` |
|---|---|
| `high` | `1.0` |
| `medium` | `0.6` |
| `low` | `0.3` |
| `null` / unrecognized | `0.3` (default) |

This mirrors the weighting used by [`scripts/generate_coverage.py`](../scripts/generate_coverage.py), so manifest confidence and coverage confidence stay consistent.

## Consumer notes (ADTE)

- **Join on `id`.** Treat `title`/`path` as display metadata that can change between releases.
- **`techniques` are canonical ATT&CK IDs** (`T####` / `T####.###`), ready to match against an incident's extracted techniques with no further normalization.
- **Poll `generated_at`** to detect a changed rule set; it is stable across no-op runs, so it will not churn.
- **Check `schema_version`** before parsing. A minor addition (new optional field) keeps `1.0`; a breaking change bumps it.

## Example (abridged)

```json
{
  "schema_version": "1.0",
  "generated_at": "2026-07-12T16:38:01Z",
  "rule_count": 2,
  "rules": [
    {
      "id": "9e8f2a3b-1c4d-5e6f-7a8b-9c0d1e2f3a4b",
      "title": "Suspicious LSASS Memory Access via OpenProcess",
      "path": "rules/windows/credential_access/lsass_memory_access.yml",
      "techniques": ["T1003", "T1003.001"],
      "lifecycle": "production",
      "confidence": "high",
      "confidence_weight": 1.0,
      "false_positive_rate": "low",
      "tuning_notes": "This rule requires environment-specific tuning:\n..."
    }
  ]
}
```

## Regenerating locally

```bash
python scripts/export_manifest.py --rules-dir rules --output docs/rule_manifest.json
```

Prints a summary line (`Exported N production rules` or `Manifest unchanged …`). Covered by [`tests/test_export_manifest.py`](../tests/test_export_manifest.py).
